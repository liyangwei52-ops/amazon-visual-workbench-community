# Amazon 电商视觉工作台

面向 Amazon 电商设计师的视觉工作台：产品图与需求 → 分析模型生成完整提示词 → 人工编辑 → 批量生图 → 保存图片资产和提示词套装。

基于开源项目 [imgx-studio/gpt-image-2-webui](https://github.com/imgx-studio/gpt-image-2-webui) 改造。当前实现以本项目源码和用户最新要求为准。

## 页面与使用流程

| 页面 | 路由 | 用途 |
| --- | --- | --- |
| API 设置 | /settings | 统一保存分析与生图的 API 地址、Key、模型 |
| 视觉工作台 | / | 多路竞品图 / 需求分析，生成并编辑提示词 |
| 提示词迁移 | /remix | 载入套装，按新产品改写提示词并生成图片 |
| 一键策划 | /planner | 产品图 + 产品信息 + 策划文档 / 文本 → 具体画面设计与多版位提示词 |
| 极简图文生图 | /simple | 图文生图 / 文生图切换，直接提交完整提示词 |
| 保存套装 | /suite | 编辑和保存套装名称、提示词与各条比例 |
| 资产中心 | /assets | 图片上传、分类、调用、预览、下载和 ZIP 备份 |
| 个人中心 | /profile | 本地头像、昵称、资料、自动归档和存储概览 |
| 各栏目生图结果 | /generate?source=栏目 | 栏目独立执行、并发、暂停、结果、重绘与手动补图 |

侧栏按上表前七项排列，左上头像进入个人中心；生图任务页通过提交任务进入。

1. 在 API 设置中分别保存分析和生图配置。所有页面读取已保存配置，编辑后未保存的值不生效。
2. 上传最多4张产品图，第一张为主产品，其余为补充资料；竞品参考图接在全部产品图之后。
3. 在工作台启用需要处理的卡片，添加参考图或填写额外需求，点击“生成提示词 N 条”；也可手写提示词。每卡参考图区的“生图时提交参考图”默认关闭：分析始终提交已添加的参考图，生图默认只带产品图；开启后下次生图才附加本卡参考图。开关随草稿保存，关闭不会删除素材或修改提示词；结果页重绘沿用原任务素材，要使用新选择请回输入页重新提交生图。
4. 设置输出比例、1K/2K和生成数量，点击“生成 N 条”。旁边“共 M 张”累计实际提交项的图片数量。
5. 在对应栏目的生成结果页查看进度；每张任务卡用数字角标切换图片，可下载或保存到共用资产中心。可到其他栏目继续提交，已运行栏目保持接收。

分析失败时，工作台在对应卡片保留原因并随草稿保存；迁移页保留本页错误说明。英文上游超时附中文解释及原请求编号，原提示词和素材保留，不自动重发。迁移继续沿用每条原来的画面目标：单品/部件细节图只迁移对应实物，不因产品照片含整套而强制展示整套。已有提示词不自动重写。

一键策划直接结合产品图、基础产品信息和策划文档/补充文本生成各版位提示词。分发兼容常见标题和正负向标签写法、分开的代码框及合并指令，完整保留德语等指定文案。确有缺失仍保留原提示词；错误下可展开“查看最近一次模型返回”，查看、复制或修正后点“从这段内容填入提示词”，只读取本地保存内容，不再次请求模型。原返回与错误在当前浏览器草稿中保留，刷新不自动重跑。

策划结果已有画面正文和负向内容、仅漏“正向 Prompt”标签时，会自动补标签并填入各提示词框，正文原样保留。此前已保存的这类失败返回，直接点“从这段内容填入提示词”即可本地恢复，无需手动补标签或重新调用模型。

策划v8加强信息图背景映射：保留本条参考的整幅背景色、光感/纹理、边缘装饰与内层面板关系，白色信息面板不再视为全幅白底。按文档逐项落实主体、细节框、尺寸线、清单、文案和位置，保留指定版式/场景/格数，输出一个确定方案；明确要求白底仍按要求执行，不给其他主题套用红色节日背景。站点、上图语言及单位按本次需求和商品事实处理，不固定德国站或德语；中文是默认的提示词说明语言。新规则用于后续手动“开始策划”；旧提示词和已生成白底图片不自动修改，旧提示词需手动调整背景或重新策划后再按需生图。最新发布状态见进度。

未配置时四入口会显示“去配置 API”引导条；极简生图只要求生图配置。保存后，常驻页面立即同步配置就绪状态与模型说明；Key不显示在引导条中。

### 三入口提示词与极简原文

- 视觉工作台默认沿用参考的结构版式：画面类型、分格/模块数量、大小层级、区域关系及各区功能保持，三宫格仍为三宫格，尺寸＋特点信息图保留对应模块。服装、小装饰、区域内产品位置/朝向等可适度变化，不重排整图。商品本身、用户指定内容及仅换商品要求优先；只有明确要求改版式时才调整结构。当前画布优先，适配区域占比与间距；这项默认不覆盖迁移或策划。
- 三入口分别推导：视觉工作台将本卡目标转成有依据的视觉表现；迁移保留旧图位/主体范围，逐项映射新实物及局部框，清除文案/负向中的旧事实；策划结合产品图、产品信息及策划文档设计每张画面，先理解产品，再将相关特征/卖点与各条策划要求对应，落实构图及整套分工，明确清单不被默认9图覆盖。成品按目标/主体、外观/动作、场景构图、光影质感和上图文字组织；15项仅内部检查，不输出空字段、推导报告或重复技术说明，有效细节及正负向完整保留，不设字数上限。设计取舍与人工示例见[提示词设计](docs/prompt-design.md)。
- 极简图文生图与文生图直接发送你填写的原文，不经过分析角色，不重组正负向，也不追加商品保真、图片身份、模型建议或画布说明。比例、1K/2K和数量仍通过API参数发送；正文里的旧画幅也不改写，如有冲突可自行修改原文。旧任务不自动转换；重新手动提交的新任务使用原文模式。
- 本图任务决定主体：只要人物、环境或后期加产品的背景时，不自动加入商品、包装或广告；明确商品展示时保留对应实物。无文字与留白不等于无商品。只有指定或要求创作的文案才排版，商品标签留在商品表面，画布/模型指令不应入画。
- 无法找到对应主体时，模型可明确说明【无法完成】；页面保留具体原因和原提示词，不把失败说明分发为生图任务。精确旧内置角色自动升级，自己修改过的角色保留；工作台角色在内部用于分析，页面不提供角色编辑或恢复默认入口。
- 三分析入口读取已保存的目标生图模型，简短说明不再强制15字段；其生图任务继续使用v2画布及模型适配，替换应用旧块且幂等。极简新任务跳过文本适配，Gemini也不插入图片身份说明。Gemini原生比例/清晰度参与请求，预计像素只在界面展示。
- API设置切换模型时显示差异，保存后用于后续请求；四入口显示当前已保存模型说明。切换不压缩提示词或改写已有草稿、套装；精确匹配的旧内置系统模板升级，用户修改过的模板保留。
- 两类模型的文字和复杂排版均需根据实际成图验收；后缀策略参考[OpenAI图像提示词指南](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)和[Gemini图像生成指南](https://ai.google.dev/gemini-api/docs/image-generation?hl=en)。本次仅验证请求和界面逻辑，未做真实付费质量对比。

### 统一参数、启用与提示词

四个生成入口共用 generation-settings.tsx 和 generation-actions.tsx：输出比例占整行，自定义比例输入占整行，清晰度和生成数量各占一列。

主生图按钮使用强调色，未就绪时显示缺少产品图、提示词或正在处理等原因；必填和启用校验仍生效。四个生图入口的批量生成栏统一固定在窗口底部，与主内容列对齐，新增提示词或滚动时仍可操作；工作台的生成提示词、迁移页的改写也放在同栏。极简页保留一个固定生成入口，套装页固定“仅保存”和“保存并返回套装列表”。页面预留操作栏高度，末尾内容不会被覆盖；手机自动换行，全屏编辑仍覆盖操作栏。

套装编辑完成后点“保存并返回套装列表”，成功后仍在套装页，上方显示空白编辑表单，下方显示已保存套装；需要继续编辑可点“仅保存”。已填写时顶部和固定底栏都能保存并返回列表，同名保存更新原套装。缺少名称、提示词、比例无效或存储失败时留在编辑页并显示原因；快速刷新不会把已退出的旧编辑内容重新打开。保存和返回均不调用模型。

空产品上传区占满一行，高度128–144px；页面正文通常为13–14px，卡片随数量自适应排列，页面最大宽度1680px。

- 输出比例包含常用比例与“自定义比例”；填写5:4、1:3等宽:高比例，再选1K / 2K，页面显示模型适配后的像素。每个任务可生成1–4张。
- 例如GPT Image 2下5:4 + 2K为2560×2048，1:3 + 2K适配为1280×3840；受模型尺寸上限影响，清晰度为计算档位，不保证每个比例的短边都到2048。Gemini使用支持的原生比例，不能精确支持时提示最接近的比例。
- 历史像素尺寸仍保留；比例输入框显示其准确宽高比，并提示原像素。编辑比例后才切换为新规则，不自动重写已有任务。
- 工作台卡头仅保留“启用”和数字编号，新卡默认关闭。没有参考图、也没有额外需求的卡片跳过分析；有手写提示词的已启用卡片可直接生图。
- 四个生成入口统一提供“全选、全不选、反选”，操作启用状态并随草稿保存；正在分析 / 改写 / 生成的卡片保持当前选择。
- 批量按钮的条数按实际可提交项计算，未启用和空提示词不计入生图条数。四入口已完成条目也可启用后重新提交，未启用条目保留原结果。
- 工作台“生成提示词 N 条”在“生成 N 条”右侧；改写按钮也显示可处理的条数。
- 提示词卡固定160px预览，内部滚动，支持全屏查看 / 编辑；界面收起不截断提示词正文。
- 旧工作台像素预设精确迁移为比例和清晰度；不能匹配预设的旧像素保留为自定义尺寸，不擅自改成相近预设。

### 并发、导航与结果

- 四个栏目各有独立任务列表、结果、暂停/停止、并发与重绘选择，可以同时生成。清空只删除本栏目任务，不改变其他栏目的进度或图片。统一API设置和资产中心继续共用。
- 同一编辑清单仅更新本次启用的条目，保留未启用的结果；在原卡片/图号等待新图返回，失败保留旧图。新增且单独启用条目也会并入本清单；完全无关的新清单单独统计，旧待确认/缺图保留且不自动重试。运行/排队只保护本栏目，其他栏目可正常提交。
- 默认全部任务同时开始，也可在生图页保存较低并发数。并发按任务计算，不固定限制为4个。
- 每张图片独立请求并行执行：5个任务分别生成4、3、2、1、1张，默认发出11个单图首次请求，GPT的n固定1；每组仍是一张任务卡。实际处理速度取决于服务商。
- GPT与Gemini均按单图并行；每返回一张立即保存。缺图显示“部分返回”和实际返回率，核查服务商结果后可手动点“补生成缺少的 N 张”，只请求缺少数量，保留已有图片；不会自动发起补图请求。
- “查看大图”在页内打开全屏原图预览，支持Base64与远程图片，保持原图比例；点击关闭或按Esc返回，不依赖浏览器允许打开Data URL新窗口。
- 当前栏目用边框、底色、加粗文字和左侧标记突出显示。每个“生成结果”链接进入自己的`/generate?source=workbench|planner|remix|simple`，仅展示本栏目任务。状态各自显示生图中、待执行或结果；栏目下“输入/编辑”回本栏表单。清空本栏后仅该栏主导航恢复输入，桌面和手机一致。导航不提交或重发请求。
- 根布局的persistent-workspace.tsx保留工作台分析、提示词迁移、一键策划和每个栏目的生图执行器。切换导航或生成结果的栏目参数只改变可见性，隐藏页面仍接收各自结果；其他栏目运行时显示对应的返回入口。
- 刷新、关闭页面或整页跳转仍可能中断连接。未确认的生图显示“待确认”，不会自动重发可能已经计费的请求。
- 再次进入/generate会检测未完成任务并恢复已保存图片。刷新恢复的排队任务等待点击“继续未发送任务（N条）”；此按钮仅执行排队项。待确认和部分返回可点“查看需核查的任务”，核查后在卡片手动重试/补图，待确认重试需确认可能再次计费。已发出的连接无法接回，不代表后台已停止。
- 同一页面刚点击“生成N条”提交的新批次仍正常自动开始。其他标签页执行时只同步进度；崩溃标签页租约过期后恢复为待确认并暂停，不自动接管付费请求。
- 分析、生图和迁移会显示等待时间；每次模型请求最多等待15分钟，包含直连/代理及完整响应体。配置连接校验15秒超时表示尚未提交模型；模型超时则保留结果不明状态，先核查服务商再决定是否手动重试。
- 服务商余额或额度不足会显示中文原因并保留原错误、请求编号，按明确失败处理；用户到服务商核查后才能手动重试。实际返回分辨率可能低于请求值，结果页会提示提交与实际像素，不自动放大或再次计费。
- “暂停后续”只暂停后续排队，继续接收已发送请求；“停止本轮”结束本地等待、保存已返回图片，随后即可重新提交，无需等模型生成完毕。未发送项显示“已停止·未发送”，点“继续未发送任务（N 条）”只执行当前清单这些条目；其他待确认项不跟随重发。已发送项可能仍在服务商处理/计费，重试或按编辑重新提交时须核查并确认。
- 每栏目使用独立Web Lock和心跳租约，同栏目跨标签不重复执行，不同栏目可同时执行；图片在IndexedDB按全局唯一任务ID保存。旧队列按原来源兼容，旧共用输入仅在所有栏目都不再引用时删除。

### 结果按提交批次查看

- 默认显示本栏目当前完整清单。五条生成后只勾选并修改第三条，会在原第三张位置重新生成，其余四张保持；不是只留下本次提交的一张。另一份全新清单先10张再15张，当前显示15张，不累计25张。
- 旧批次存在待确认/部分返回等保留任务时，通过“查看批次”切换历史；查看不发送请求、不修改图片。全选/全不选/反选与重绘仅作用于正在查看的批次，切换清空勾选，新提交/刷新回到最新。
- 原位重绘保留原卡片、图号与批次；生图期间查看历史仍继续接收结果。并发、暂停、停止、清空是栏目执行控制，查看历史不能解除运行保护。“清空本栏目”包括该栏保留的历史批次。
- 结果清单与素材批次分离，旧任务字段缺省时按原输入批次兼容。无关且完整结束的旧清单仍可被新清单替换，不保证永久保存每次已结束批次；同一清单的未启用结果不因局部重交删除。历史字段不足时保守合组，不按提示词或数量猜测拆分。

### 选择结果并原位重绘

- 结果页可全选、全不选、反选，或点击“勾选失败/缺图”；也可以勾选整条任务。
- 一个任务有多张时，用数字切到需要的图片，再勾选“选择第 N 张重绘”。“重绘所选 N 张”只生成所选数量。
- 重绘沿用原提示词、比例、清晰度和原产品 / 参考素材，读取API设置中当前保存的配置；在原卡片、原图号替换，不新增任务卡，也不改变图号、任务数量或顺序。新图返回前继续显示旧图；未选中的图片不变，失败或结果不明也保留旧图。它会发起新的付费请求；待确认结果请先核查服务商。
- 运行中 / 排队任务需先处理，才可重绘。选择和反选本身不会发送请求；刷新后结果选择清空，不自动重绘。失败时“重试未完成的 N 张重绘”仅请求剩余位置，已替换的新图不重跑。历史追加的重绘卡继续保留，不自动删除；“仅补缺图”仍保留独立入口。资产中心通过图号版本识别新图，不覆盖此前保存的资产。

### 多张图片只返回部分时

1. 查看任务卡的“已返回 X/Y 张”和提示信息；数字角标对应计划图片数量，空角标不代表已生成。
2. 先核查服务商结果，再点击“补生成缺少的 N 张”。这会发起新的生图请求，可能产生费用；仅补缺少数量，保留已有图片。
3. 处理缺图前不要清除网站数据。未启用的缺图条目保留；启用后再次提交则按本次编辑在原位置生成，旧图保留到新图成功返回。也可主动删除不再需要的任务。

旧任务中未返回的图片不会因更新应用而自动找回，刷新也不会自动重发请求。

### 模型尺寸、策划与套装

- 当前选择的画布优先于提示词旧画幅：提交时对齐全文中明确的画布比例与像素，加入首尾画布约束，保留商品实测尺寸、形状、局部照片框和完整正负向内容。任务预览与图片归档使用实际提交的版本；原编辑卡的提示词不被自动覆盖。
- 结果图按原图实际像素检查，明显偏离提交比例时显示“比例不符”，像素大小明显不一致也会提示。保留原图，不裁剪 / 拉伸、不自动重试；服务商仍可能忽略要求，不能保证仅修改提示词就控制所有上游输出。
- GPT Image 2按模型规则对尺寸就近适配，包括16像素对齐、长边、长短边比和总像素限制；已合法的尺寸原样提交。
- Gemini按原生比例与清晰度提交，不套用GPT的16像素规则。界面显示预计尺寸，结果显示实际返回尺寸。
- 策划文档支持 XLSX / DOCX / CSV / TXT，在浏览器提取文字及内嵌图，向模型发送提取内容；不是把原始Excel文件直接传给模型。
- 共享分析请求上限为4MiB，图片Data URL合计3.5MiB，全部产品图与参考图合计最多32张。超限应明确阻止提交，不静默丢图或截断提示词。
- 套装只保存名称、完整提示词和各条比例 / 自定义比例（兼容旧像素），不保存图片、Key、清晰度、数量或生成模式。
- 图片资产保留原图；用于分析和生图的输入副本可按预算压缩。清除浏览器网站数据会删除本地内容，请及时备份。

## 本地运行

新检出项目使用 Node.js ≥20.9.0；最近验证环境为 Node.js 24。安装依赖后启动：

```powershell
npm ci
npm run dev
```

生产模式：

```powershell
npm run build
npm run start
```

开发默认使用Webpack，也可用 npm run dev:turbo。不要覆盖正在提供服务的构建目录；需要同时运行测试服务时用 NEXT_BUILD_DIR 指定隔离目录，先构建，再用相同目录启动。

### 缓存与安全清理

- `.next`及`.next-verify*`是可重新生成的构建产物。删除前核对正在运行的服务及其构建目录，临时验证结束后停止对应服务并清理隔离产物；保留需要立即运行的当前生产构建。
- `tsconfig.tsbuildinfo`和`.next/cache/turbopack`等编译缓存可重新生成；清理会使下次编译重新计算，不影响浏览器中保存的数据。
- `verification/`包含历史真实测试图片、记录和浏览器资料，`backups/`包含可恢复副本；本次保留，不当作普通缓存。TypeScript与ESLint已排除这两个目录和历史`.next-verify*`产物，避免重复扫描；正常源码和当前构建类型继续检查。
- 10月19日清理前的源码/配置/文档及被删SVG副本在`backups/cleanup-20261019/source-before.zip`，清单与验证在`verification/cleanup-20261019/`，均不随网站发布。现有`node_modules`、环境配置、旧草稿兼容代码及真实结果恢复功能保留。

本地OpenLux代理需设置服务端允许列表 ALLOWED_API_ORIGINS=https://api.openlux.ai；这里不填写Key。服务商地址必须是已配置的HTTPS源，不能开放任意地址代理。

## 安全与已知限制

- 没有账号权限隔离；同一浏览器配置文件中可访问本站数据的人可以读取本地内容。
- Key保存在用户浏览器localStorage，不能把它描述为加密保险箱；不记录、导出或提交密钥。
- 云端仅对通过允许列表校验的精确OpenLux接口使用浏览器直连，其他接口经本站代理；失败不自动切换路径重发。
- 匿名文档上传已禁用，/api/blob-upload返回410。
- 站内持续接收目前覆盖工作台分析和统一生图；一键策划 / 提示词迁移的分析仍由各自页面持有。
- 暂缓事项为注册登录和云端资产同步；第三方API可用性、速率与生成效果取决于服务商，不能承诺任意模型都已适配。
