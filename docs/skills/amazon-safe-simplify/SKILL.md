# 工作台精简边界

在目标项目根目录读取 AGENTS.md、AI_QUICKSTART.md、docs/AI_HANDOFF.md 和 docs/progress.md，以当前源码与用户最新要求为准。若目标不是 Amazon 电商视觉工作台，不套用本技能的项目约束。

## 选择可以删除的内容

- 先核对 Git 未提交及未跟踪文件。以工作区当前内容为基准，不能用 HEAD 覆盖已有工作。
- 删除模块前同时核对路由入口、静态和动态引用、样式、测试、配置及文档。搜索不到导入只是证据之一；Next 的 page、layout、route 和元数据文件可能由框架自动发现。
- 优先清理不可达旧界面、仅被旧界面使用的组件和无效果包装。合并重复代码时保留调用顺序、异常处理、请求次数和保存时机。
- 文件名中的 legacy、旧字段和禁用接口不等于冗余。旧提示词识别、草稿迁移、部分结果恢复和返回410的上传接口须按实际兼容用途判断。
- 历史日志、测试输入、图片及未跟踪代码可能是用户资料。未确认用途时保留；删除当前清理范围内的源码前保留可恢复副本，避免备份进入发布包。

## 保留运行语义

核心业务规则以项目入口文档为单一来源。尤其核查：统一已保存API配置、完整提示词和商品事实、当前画布优先与模型适配、全部产品图及身份顺序、每张独立首次请求和立即保存、仅手动补缺图、多标签执行锁、站内任务连续性、存储键及旧数据恢复、服务商允许列表与匿名上传禁用。

“精简项目”本身不授权删除正在使用的页面、压缩提示词正文、清除浏览器数据、重试付费请求、新增账号系统或发布线上。若需要产品取舍，先完成有证据支持的独立清理，再明确列出待决定项。

## 验证与交付

修改 Next 相关代码前读 node_modules/next/dist/docs/ 的对应指南。按改动选择类型检查、ESLint、隔离构建和现有模拟回归；先检查脚本，不能盲跑真实付费测试。不覆盖正在提供服务的构建目录。

报告实际删除或合并项、引用证据、恢复位置、检查结果和未验证范围。按 AGENTS.md 同批同步 README、progress 及必要的接手文档，明确源码修改、本地服务更新与线上发布的区别。
