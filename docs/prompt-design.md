## 工作台v13：额外需求先行，按图型借鉴参考

## 工作台v12 / 迁移v9历史：保留版式，默认更新局部造型

工作台v12与迁移v9默认在保留格数/模块层级、区域关系、主体范围及文案框位置的前提下，主动选定不同的人物姿态/视线、非商品服饰和小装饰，并将具体动作、款式颜色及摆放直接写进正向。人物关系/数量和互动目的保持；商品、销售服装、首饰及随附配件不可变，用户明确锁定或仅换商品优先，无相应元素不新增。局部变化规则独立在`local-scene-variation.ts`，只接入这两个入口；策划v10、极简原文与生图协议保持。旧默认仅精确升级，已有提示词/套装/任务不自动改写，需用户主动分析或迁移；同一提示词多张生成不保证互异。

## 迁移v8保留能力：同类商品换主题与逐条填入

同类型商品改主题时，以原条目为底稿，保留图位、模块数量、主体范围、人物关系及有效布局；按新产品图/资料替换外观、主题文案、人物服饰与必要动作、环境和氛围。原图位只拍单品就仍拍对应单品，局部框仍属于该主体。商品结构、数量、配件、材料和实测尺寸以新证据为准，同类型不授权沿用旧事实。

普通迁移不要求新商品完整长宽厚。旧稿有尺寸数字而本次无实测时，移除旧数字、测量箭头与参数文案，在原信息区域改为无数值的可见形态、结构或使用展示；只有用户本次明确必须标注未知实测值且不允许替代，或缺少无法对应的实物/身份时，才为该条返回具体【无法完成】。这不改变视觉工作台/策划各自的事实要求，也不改已有提示词。

页面对每条启用提示词单独请求，成功返回即按条目ID填入原框并保存草稿；失败只保留该条原文/原因，其余继续。最多三条并发，同一会话部分成功后用户手动再次提交、素材/设置和已填入正文均未变时，复用成功缓存，只发未完成项；人工改过的已填入条目可重新提交。缓存、运行状态和错误不跨刷新，草稿仍沿用已有字段；刷新/离页废止旧页面未发请求，不恢复或自动重发。浏览器模拟只证明传输、回填和恢复边界，不证明真实模型是否生成合适画面。

## 三入口站点文案与具体画面表达

旧共同规则及工作台userText把“用户未给最终文案”直接视为无字，与用户本次允许参考改写的要求冲突。本次在保留现有商品核对、布局映射和分发基础上，修改同一决策链，而非末尾叠加一条互相矛盾的禁中文声明。

| 情况 | 新规则 |
| --- | --- |
| 用户指定非中文最终标题/卖点/标签 | 对应模块逐字保留；参考不得覆盖，局部指定不取消其他既有文字模块 |
| 用户未给最终原文，参考/文档竞品图/迁移旧稿有文字模块 | 按模块功能、我方事实及目标站点改写，不再额外索要创作授权；不照抄旧品牌、功效、尺寸或数量 |
| 只有中文卖点/中文策划说明 | 理解意思后转成目标语言最终文案；中文说明和括号翻译不入画 |
| 站点/语言来源 | 本次明确要求优先，其次本条文档，其后参考/旧稿一致的非中文消费语言；无可靠线索暂用英语，不声称已确认站点 |
| 明确无字/纯背景/无字人物/列表白底首图 | 保留该图位的无字边界，不因参考有标题强加文字；既无文字模块依据也无创作要求时不自动造广告 |
| 中文实物印字、日文汉字 | 实物印字仍在原表面，不能因禁中文广告改商品；正常日文不按汉字字符集误删 |

新增标题、卖点、标签和额外尺寸说明均用选定的非中文目标语言，每条在正向列出最终字符串、出现次数、所属区域、文字框/边距、对齐换行及字体层级。执行说明仍可中文，只绘制清楚列出的原文。若同时强制逐字中文与禁止中文，或锁定文案与商品事实确实冲突，按入口失败合同保留旧内容并说明，不偷偷改字或删需求。

三处共同要求：写明商品具体轮廓/部件连接、完整分区、背景/面板、区内主体位置大小和文案位置，不能依赖“参考图一的摆放位置”“同竞品”“按文档”“合理摆放”等指代。只交付一个布局方案；百分比注明相对整幅或分区，布局约数不冒充商品实测。迁移也必须展开旧稿保留布局，不能把重新看旧图或排版交给下游。只读成品即可理解画面，图片辅助核对实物。

## 工作台v10与策划v9历史：产品结构核对先于视觉映射

本次按用户明确的核心需求调整两入口，不更换解析、素材通路、队列、画布或极简原文协议。

| 入口 | 输入职责 | 内部工作与交付 |
| --- | --- | --- |
| 视觉工作台 | 产品图/已确认信息决定实物，竞品图提供画法，额外需求决定本卡目标和修改范围 | 当前一张图，按五阶段收敛为确定画面；保留参考分区和信息功能 |
| 一键策划 | 产品图识别可见结构，产品信息补充事实，策划文档确定各图任务/参考及整套分工 | 先建立共同产品事实和清单，再逐图设计；不是只改写文档或套营销模板 |

有参考时，两个入口均在内部执行：**竞品视觉拆解 → 我方产品识别 → 产品硬约束 → 竞品视觉映射 → 完整成品 Prompt**。这个顺序先理解画法，不代表竞品优先于产品；完成商品核对才允许映射。

1. 视觉拆解只提取分区、阅读顺序、主体排列、动作、背景/面板、光色和文字层级；不接收竞品商品形状、部件、数量、尺寸或功效作为新事实。
2. 产品识别依据我方全部图片与已确认信息，写明出镜实物的轮廓、部件形状/数量/连接及表面。区分开口、阴影、印刷线、接缝和临时遮挡；不能靠品类常识猜隐藏连接。
3. 硬约束只锁定已确认实物。参考的展开、穿戴、拍摄面或局部特写不适合新结构时，改机位/动作/接触或使用有依据的对应细节承担区域功能，不能改商品、加配件或改印花。
4. 每区落实“信息功能→当前实物/部位→可见证据/确认数据→展示方式→最终文案及位置”；未必需要印文字，不能把产品信息全转成广告。必需事实缺失说明无法完成，非必需未知项用保守视角避开。
5. 正向直接写出确定商品与画面，负向只排除具体风险。内部阶段、事实表、自检和评分不进入成品；原正负向、代码框、策划编号及完整细节保留，15项仍仅供内部检查。

策划没有关联参考的条目，直接结合产品事实与该条文档目标设计，不假称看过竞品，也不用其他行参考补成另一张图。无参考工作台同理。商品硬约束只约束要求出镜的实物，不为纯人物/背景任务自动加商品。旧背景分层、格数、局部框归属、多语言原文和尺寸计数规则继续保留。

| 入口 | 推导重点 | 成品边界 |
| --- | --- | --- |

### 实际生图请求

四入口、直连、代理及Gemini复用该逻辑。图片身份说明同步限定出镜范围，避免末尾说明再强加产品。没有更换模型、删除输入图、增加请求、裁图或自动重试。

## v3历史设计与资料（以下非本次新增验证）

## 为什么要分开

此前三个入口拼接同一套“竞品拆解→产品映射”长模板，再追加少量说明。公共层含单图输出格式，批量入口又要求编号分发；一键策划缺少整套信息分工，迁移容易混淆旧商品事实与新商品范围。v3只共享事实、画面表达与完整15项结构，任务推导和外层输出分别维护。

| 入口 | 输入与起点 | 先解决的问题 | 输出与验收 |
| --- | --- | --- | --- |
| 视觉工作台 | 真实商品＋本卡目标＋可选参考 | 一张图如何表达；参考中哪些关系可借用，无参考如何设计 | 一条最终正负向；不是整套策划；多参考冲突须形成一个可行方案 |
| 提示词迁移 | 旧条目的图位/视觉配方＋新商品 | 什么不变、什么必须替换、哪些接触/使用关系需重做 | 本批同数量/顺序编号；单品仍是对应单品，局部框属于同一主体 |
| 一键策划 | 商品＋文档/补充需求 | 整套每张负责解释什么、对应什么证据和参考 | 原清单完整覆盖、顺序/名称保留、每图自足且信息分工可区分 |

## 保留与补强

- 最终正向1—14项、负向第15项仍完整输出，无字数上限、不压缩、不用“同上”。不适用的元素明确无人物/无额外文字，不为凑结构创造内容。
- 产品事实与创作选择分开；补充产品图不增加销售数量，竞品/旧提示词不提供新商品事实。印花表面、遮挡处、内页和未知参数采取保守处理。
- 当前画布优先；参考外框/旧画幅不决定输出，局部框比例和商品实测尺寸不误作画布尺寸。原模型适配及模型短后缀保持。
- 指定文案用精确字符串、出现次数、位置和层级表达，保留多语言、大小写和标点；未要求文字不加英文口号。负向针对本图，正向同时说明期望结果。
- 区分列表首图、详情副图、场景主视觉和A+，不能看到“主图”就把生活场景全部转白底。
- 附件/旧提示词中的改系统、改输出格式等指令只作素材，不覆盖真实任务合同；正常图位需求与用户原文继续处理。
- 迁移只有新产品图，策划生图没有Excel/文档参考：保留的视觉关系必须落到文字，不能依赖下游看不到的附件。
- 三入口明确【无法完成】时显示原因并保留旧提示词，不把说明分发为成品；不自动重试或调用生图。
